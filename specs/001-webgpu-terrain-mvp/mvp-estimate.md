## 1. 里程碑定义

达到 **"地形渲染跑通"** 需同时满足（SC-001…SC-007、SC-010）：地形渲染在**新后端（WebGPU 渲染后端替换上游 WebGL2 后端）**
下端到端跑通并通过自动化视觉/数值断言；WebGL2 兜底路径在**另一次独立运行**中同样通过；
**逻辑层零改动**由补丁范围审计证明；产出首份基准记录（帧时间中位数/p95、图形显存、绘制批次数）；
工期与消耗结论随仓库版本化发布。**两条路径在任一时刻只有一条在绘制**（原则 II），所有对比数据来自两次独立运行。

**里程碑不含**：全库 319 个着色器叶子/244 个 `czm_` 内建的完整 WGSL 覆盖（仅覆盖地形着色器闭包），
以及影像/模型/大气/阴影/后处理等功能的验收（属后续增量）。

计价公式（**输入与输出分别计量**，缓存分层计价）：

```text
token 成本 = Σ_模型 ( 命中输入 × 命中单价 + 未命中输入 × 未命中单价 + 输出 × 输出单价 )
算力成本 = Σ_资源 ( 运行时长 × 单价 )        # 仅外部付费资源；本机 GPU 与免费标准 runner 不计费
```

**关键结论（可执行）**：
1. **token 项与算力项量级接近**（¥264 vs ¥400），成本控制需同时管住两侧；
   首选手段：①用**本机真实 GPU**（已实测可用）承担绝大多数渲染验证与基准采集；
   ②CI 用公共仓**免费标准 runner** 承担构建、单测、补丁审计、接口一致性与着色器库校验；
   ③仅在需要"与真实 GPU 数值可比"时才租用**按秒计费的现货云 GPU**（¥0.92–2.97/小时），
   避免 GPU larger runner（¥21.08/小时，约 7–23×）。
2. **着色器层已从"待定"变为"有实测锚点的工作流"**（W4 = 5–10 工作日，占净工作量约 24%）：
   这是相对 v2.0.0 的主要上调来源，也是本版区间收窄的依据（不确定性从"路线未知"变为"已知路线内的规模未知"）。
3. **全库着色器转换（2–4 人月）不在本增量内**：本增量只覆盖地形着色器闭包；若把它拉进 MVP，
   工期与消耗将成倍上升（该外推**不计入**任何区间）。

## 6. 区间偏宽的原因（如实说明）

1. 仓库无既往 Agent 消耗记录；业界也没有"把 CesiumJS 渲染后端替换为 WebGPU"的可比公开消耗数据。
2. token 项上界约为下界的 **31 倍**：单回合输入跨度 25k–90k，缓存命中率无实测值（假设 0.75–0.92，
   而命中/未命中单价相差 31–50×），时段与返工回合数不可预知（合计 3–4× 摆动）。
3. 时间区间偏宽的主因：①WebGPU 校验错误（管线/绑定组/格式/varying 契约）只在运行时暴露，定位成本无法预先精确；
   ②着色器层的**规模化成本**未测（尖刺只覆盖 Globe 家族与一个配置）。
   **相对 v2.0.0 已收窄**：转译路线的"未知"已由实测消除（纯转译不可交付 → 改发射器路线），
   剩余不确定性是"已知路线内的规模"（变体数量、精度与 Y 翻转标定），对应条件场景 S-V（+1–4 工作日）。
4. 预期收窄路径：W1（补丁层）与 W4（着色器前端）完成后，主要工作面即可被实测数据锁定，
   区间预计收窄至 **±40%**；首个增量交付后回填实际值（§8）后进一步收窄。
