## 1. 里程碑定义

达到 **"地形渲染跑通"** 需同时满足：WebGPU 新路径与 WebGL2 兜底路径在同一上层 API 下渲染同一固定数据集地形，
通过自动化视觉/数值断言（两条路径都跑），并产出首份基准记录（帧时间中位数/p95、图形内存、绘制批次数），
且工期与消耗结论随仓库版本化发布。即 SC-001…SC-007 覆盖的四项齐备。

## 2. 时间区间（按工作流拆分）

| 工作流 | 时间区间（工作日，AI 净工作量） | 主要消耗驱动因素 |
|---|---|---|
| W1 渲染管线与地形绘制 | **3.0 – 6.0** | WGSL 管线与绑定布局、瓦片几何与裙边构建、公开高程源解码与固定数据集生成、GL→WebGPU 深度/坐标换算、多瓦片接缝正确性、设备丢失恢复 |
| W2 双路径能力探测与兜底 | **1.0 – 2.0** | 2 秒探测上限、能力下限判定、回退原因分类、可观察提示、设备丢失后恢复或降级 |
| W3 验证资产与测试基建 | **2.5 – 5.0** | 固定地形数据集获取与落盘、Playwright 采集脚手架、像素对比与差异图、统计断言、容差标定对照实验 |
| W4 持续集成与基准基建 | **1.5 – 3.0** | 双路径流水线编排、无 GPU 环境降级、基准门槛与历史序列、20 分钟总耗时目标、许可证检查 |
| W5 开源交付与文档 | **1.0 – 2.0** | LICENSE/CONTRIBUTING/可复现构建说明/降级与盲区说明/演示页说明 |
| W6 治理、评审与结论收尾 | **0.5 – 1.5** | 一致性分析、评审往返修订、评估结论版本化与实际值回填机制 |
| **合计** | **9.5 – 19.5 工作日** | **日历跨度 2 – 4 周**（含人工审批等待，按 1 主 Agent 串行 + ≤3 子 Agent 并行） |

**时间口径前提**：由 Agent 工作流执行，人工只承担审批与验收；日历跨度 = 净工作量 ÷ 并行度（1.5–2.0）
+ 评审等待（按每阶段 0.5–1 工作日计）。**不设硬性交付期限**（SC-008）；
超出区间时以书面形式说明偏差原因与新预期。


**关键结论（可执行）**：本项目 MVP 的 AI/Agent 消耗**几乎全部由算力项而非模型 token 项决定**
（token 项合计不超过 ¥115，算力项上限可达 ¥851）。因此控制成本的手段按优先级是：
① 每次提交的双路径验证与**相对**基准用公共仓标准 runner 承担（免费，方案已核实可行）；
② 绝对性能与带时间戳的剖析用**按秒计费的现货云 GPU**（¥0.92–¥2.97/小时），
   而不是 GPU larger runner（¥21.1/小时，且**公共仓也始终计费**，约 7–23×）；
③ 把 Agent 任务调度在空闲时段并控制重试退避（token 项 2× 摆动）。

## 6. 区间偏宽的原因（如实说明，无历史基线）

1. 仓库当前为**空仓**，没有任何既往 Agent 消耗记录；业界也没有"WebGPU 渲染路径移植"的可比公开消耗数据。
2. token 项上界约为下界的 **30 倍**：单回合输入跨度 25k–75k，缓存命中率无实测值（假设 0.75–0.92，
   而命中/未命中单价相差 31–50×），时段与返工回合数不可预知（合计可造成 3–4× 摆动）。
3. 时间区间偏宽的主因是首次采用"**双画布分层 + 自定义公开 TerrainProvider + 上游四叉树调度**"这一组合
   （技术依据见 [research.md](./research.md)），其集成风险只能在实现阶段实测收敛。
4. 预期收窄路径：首个增量交付后回填实际时间与消耗（§7），区间预计可收窄至 **±40%**。

## 7. 版本化与基线复用（FR-028）

- 本结论随仓库版本化发布：人类可读版 `mvp-estimate.md` + 机器可校验版 `mvp-estimate.v1.json`
  （CI 文档契约测试按 `contracts/mvp-estimate.schema.json` 校验，并断言

  （含缓存命中/未命中拆分）、实际算力费用、偏差说明；并作为后续增量的估算基线。
- 触发修订的情形（范围/判据变化、数据源变化、执行方式或并行度变化、单价或峰谷规则变化）见
  `revisionPolicy`；修订必须递增版本并保留历史版本。
